    17→    17→### Critical Bug Fix: Inpainting Algorithm
    18→    18→- **Bug**: The inpainting algorithm was not processing boundary pixels. The code marked all boundary pixels as `processed` before they were actually inpainted, causing the `if (processed[idx]) continue` check to skip them. This meant NO masked pixels were being reconstructed.
    19→    19→- **Fix**: Removed the premature `processed` marking. Now boundary pixels are properly processed first, then their neighbors are added to the queue, and the fast marching method propagates inward correctly.
    20→    20→- **Verification**: VLM confirmed the watermark is now fully removed with smooth gradient reconstruction. Output pixel values match expected gradient values within ±5 tolerance.

   125→   125→## Task ID: 3-a
   126→   126→Agent: store-agent
   127→   127→Task: Update Zustand store with undo/redo functionality and history tracking
   128→   128→
   129→   129→### Changes Made
   130→   130→
   131→   131→#### store.ts (`src/lib/store.ts`)
   132→   132→
   133→   133→**New Types:**
   134→   134→- `LastAction`: Union type tracking operations ("upload" | "remove-watermark" | "add-watermark" | "transform" | "optimize" | "reset")
   135→   135→- `ImageInfoSnapshot`: Serializable snapshot of ImageInfo (excludes `File` object, keeps dataUrl + metadata)
   136→   136→- `WatermarkConfigSnapshot`: Serializable snapshot of WatermarkConfig (excludes `logoFile` File object, keeps all other fields)
   137→   137→- `HistorySnapshot`: Combined snapshot type storing { originalImage, processedImage, step, transformConfig, watermarkConfig, lastAction }
   138→   138→
   139→   139→**New State Fields:**
   140→   140→- `history: HistorySnapshot[]` — Array of state snapshots for undo/redo navigation. Initialized with `[initialSnapshot]`.
   141→   141→- `historyIndex: number` — Current position in history. Always points to the snapshot representing the current state. Initialized to `0`.
   142→   142→- `lastAction: LastAction | null` — Tracks what the last operation was. Initialized to `null`.
   143→   143→- `canUndo: boolean` — Computed from `historyIndex > 0`. Updated on every history change.
   144→   144→- `canRedo: boolean` — Computed from `historyIndex < history.length - 1`. Updated on every history change.
   145→   145→
   146→   146→**New Methods:**
   147→   147→- `pushHistory(action?: LastAction)` — Pushes a snapshot of the current state to history. Truncates any redo entries beyond `historyIndex`. Updates `canUndo`/`canRedo`.
   148→   148→- `undo()` — Decrements `historyIndex`, restores state from `history[newIndex]`. Restores: originalImage (reconstructing File from dataUrl), processedImage, step, transformConfig, watermarkConfig (logoFile set to null), lastAction, outputFileName, isProcessing (set to false).
   149→   149→- `redo()` — Increments `historyIndex`, restores state from `history[newIndex]`. Same restoration logic as undo.
   150→   150→
   151→   151→**Helper Functions (private, not exported):**
   152→   152→- `createImageInfoSnapshot()` — Strips File object from ImageInfo, producing ImageInfoSnapshot
   153→   153→- `createWatermarkConfigSnapshot()` — Strips logoFile from WatermarkConfig, producing WatermarkConfigSnapshot
   154→   154→- `dataUrlToFile()` — Reconstructs a File object from dataUrl + filename + mimeType (using atob + Uint8Array)
   155→   155→- `restoreImageInfo()` — Reconstructs full ImageInfo from ImageInfoSnapshot by creating File from dataUrl
   156→   156→- `restoreWatermarkConfig()` — Reconstructs WatermarkConfig from WatermarkConfigSnapshot (logoFile = null)
   157→   157→- `createSnapshotFromState()` — Creates a complete HistorySnapshot from the current AppState
   158→   158→
   159→   159→**Modified Existing Methods:**
   160→   160→- `setOriginalImage(image)` — Now automatically pushes to history before making the change. Truncates redo future. Creates snapshot of the state AFTER the change (including the new image). Sets `lastAction: "upload"` when image is set, `null` when cleared.
   161→   161→- `setProcessedImage(image)` — Now automatically pushes to history before making the change. Truncates redo future. Creates snapshot of the state AFTER the change (including the new processedImage).
   162→   162→- `reset()` — Now also resets history state: `history: [initialSnapshot]`, `historyIndex: 0`, `lastAction: null`, `canUndo: false`, `canRedo: false`.
   163→   163→
   164→   164→**Undo/Redo Design:**
   165→   165→- Standard pattern: `history[historyIndex]` always represents the current state.
   166→   166→- When a new action modifies state, the state AFTER the change is pushed as a new snapshot, and `historyIndex` advances.
   167→   167→- Undo restores `history[historyIndex - 1]`, decrementing `historyIndex`.
   168→   168→- Redo restores `history[historyIndex + 1]`, incrementing `historyIndex`.
   169→   169→- Any new action truncates the redo future (entries after `historyIndex`).
   170→   170→- Shallow cloning of ProcessedImage and TransformConfig in snapshots to prevent shared-reference mutations.
   171→   171→
   172→   172→**Known Limitation:**
   173→   173→- `WatermarkConfig.logoFile` (File object) cannot be serialized into history snapshots. When restoring from history, `logoFile` is set to `null`. Users who undo/redo after applying a logo watermark will lose the logo file reference and need to re-upload it.
   174→   174→
   175→   175→**All existing functionality preserved:** All original types, state fields, and setter methods remain intact. No breaking changes to existing component imports or usage.

   179→   179→- Dev server: Running cleanly, no compilation errors after store update
   180→   180→- All 10 component files referencing `useAppStore` continue to work (no field removals or type changes to existing exports)
